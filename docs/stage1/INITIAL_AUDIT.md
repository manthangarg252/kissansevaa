## 1. Executive Classification Matrix

| Module / Capability | Status at Audit Start | Observed Gaps & Defects |
|---|---|---|
| **Crop Disease ML Service (V1 DINOv2-S/14 + FAISS)** | Already implemented (Preserve) | V1 (`2,144` vectors, `67` classes) active on `:8000`; `V3` hybrid + 14-crop gate in shadow mode (`ENABLE_V3_SHADOW=true`). Must remain untouched in V1 production mode. `16/16` FastAPI tests pass. |
| **Centralized Gemini Integration Layer** | Broken / Incomplete | `backend/services/geminiService.js` hardcodes `gemini-3-flash-preview` (observed `429 RESOURCE_EXHAUSTED` daily quota 20 RPD hit during baseline test!). Returns fabricated silent dev fallbacks (`confidence: 0.91` for livestock, canned Wheat Yellow Rust / generic string responses), lacks timeout/retry/rate-limit/request-id/usage accounting, and lacks structured `service_unavailable` / `rate_limited` status propagation. |
| **Dedicated Weather Intelligence** | Missing | Dashboard shows hardcoded weather text (`R.string.dashboard_weather_summary`, `"Next 48 hrs provide an ideal dry window..."`). No backend weather routes/controller/Open-Meteo adapter, no `WeatherCache` Mongo model, no Room entity, no Compose `WeatherScreen`, no rainfall/spray/heat/cold rules engine. |
| **Crop Diagnosis Gemini Fallback & Flow** | Partially implemented | Auto-falls back only on DINOv2 outage; retains explicit attribution and treatment withholding on `needs_review=true`. **Missing:** explicit farmer-consent second-opinion endpoint (`POST /api/crop/second-opinion` or consent flag) for V1 `needs_review=true`, V3 disagreement/unsupported crop review, and structured side-by-side comparison UI in Android `CropDiseaseScreen`. |
| **Livestock Health Assistant** | Partially implemented (Stub-level) | Single basic `POST /api/livestock/analyze` route; drops to fake `confidence: 0.91` mock on Gemini error. **Missing:** `GET /api/livestock/history` endpoint, Room `LivestockAnalysisEntity` & DAO, structured clinical inputs (species/age/symptom duration/fever/appetite/milk drop/ulcers/isolation), urgent vet escalation flags, explicit prohibition on unverified prescription drug/antibiotic dosages, and safety UI. |
| **Smart Crop Planner & Care Calendar** | Missing | No backend planner routes/controller/models (`CropPlan`, `PlannerTask`), no deterministic 7-day crop/stage/weather/soil task generator, no Gemini plan refinement hook, no Room entities, no Compose `CropPlannerScreen`, and no WorkManager reminder notifications. |
| **Market / Mandi Prices** | Partially implemented | `DATA_GOV_IN_API_KEY` IS configured and live stats showed 93 records, with vegetable/fruit/crop categorization and 15-min refresh timer. **Defects/Missing:** Android `MarketPriceEntity` lacks `category` column; silently falls back to `simulateMarketUpdate()` random +-2.5% drift when API fails; UI/backend lack district/mandi drilldown filters, multi-mandi price comparison, persistent user favorites (`MarketFavorite`), and honest live/cached/stale source badge. Note: AI market strategy card in `PricesRepository` falls back silently to static Cotton text on network error. |
| **Government Schemes & Subsidies** | Partially implemented | Only `POST /api/schemes/recommendations` using ungrounded `generateText`, while Android `SchemesRepository` only loads static `CatalogData.SCHEMES` without backend catalog sync or bookmarks. **Missing:** verified curated scheme dataset (`PM-KISAN`, `PMFBY`, `KCC`, `PM-KUSUM`, `Soil Health Card`, `e-NAM`, `PKVY`, `PMKSY`, `NLM`, state schemes) with official `.gov.in` links & timestamps, `GET /api/schemes` filterable catalog, `POST /api/schemes/eligibility`, `POST /api/schemes/explain`, saved/bookmarked schemes in Mongo + Room. |
| **Multilingual Chatbot** | Partially implemented | Single-turn `POST /api/chat` saving `ChatHistory`. **Missing:** category/mode tool-grounding (Weather/Mandi/Schemes/Crop/Livestock/Planner DB context injection), multi-turn conversation `sessionId` & recent turn history, `GET /api/chat/history` & `DELETE /api/chat/history`, user-scoped Room `chat_messages` isolation. |
| **Voice STT, TTS & Form Extraction** | Partially implemented | `SpeechToText` / `TextToSpeechEngine` interfaces, `MicButton`, `VoiceFormFillButton`, and `/api/extract-fields` exist in Compose UI and backend. **Needs hardening:** explicit field-level voice extraction telemetry/schema validation via centralized Gemini service, verification of language switching (`en/hi/bho/mr/pa/sa`) across all new screens, and audio lifecycle tests on new Planner/Livestock/Schemes flows. |
| **Offline Room Caching & User Sync** | Partially implemented | Room v3 (`KissanDatabase`) caches 7 tables and `DataSyncWorker` runs 15-min periodic pulls for IoT/Prices/Traders. **Defects/Missing:** Room tables have no `userId` isolation (data can leak across user sign-out/sign-in!), no `SyncOperationEntity` offline mutation queue (`POST`/`PATCH` replay), no backend `POST /api/sync` batch idempotency endpoint, and `MarketPriceEntity` misses `category`. Explicit `Migration` path MUST increment DB version safely without destructive fallback. |
| **Call-Agent Telephony Integration** | Not present (Requires external action & contract) | Confirmed via repo search: no telephony/IVR/call-agent service exists. Stage 1 scope prohibits building a replacement call agent; only an integration adapter/webhook contract (`POST /api/integrations/call-agent/webhook` / advisory context hook) will be documented if needed. |
| **Live External API Keys & Physical Device** | Requires external action | `GEMINI_API_KEY` reaches live API but `gemini-3-flash` Free Tier 20 RPD quota hit `429 RESOURCE_EXHAUSTED` during baseline test (other models/paid key to be verified). Samsung A35 physical device (`RZCXC17RFEW`) is PIN-locked on user desk. |
