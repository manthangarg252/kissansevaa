# Full-Dataset FAISS Index Import & Rollback Procedure

This document describes how to safely import, verify, stage, activate, and roll back versioned DINOv2 + FAISS assets generated by `ml-service/notebooks/KissanSevaAI_Phase1_Full_Dataset_Colab.ipynb` **without overwriting the existing production `v1` baseline (`ml-service/model_assets/`)**.

---

## 1. Existing Production Assets (Keep Intact)

Never overwrite `ml-service/model_assets/` directly before validation.  
Currently active baseline (`v1_pilot_2144`):
- Directory: `ml-service/model_assets/`
- Contents: `dinov2_vits14_cls_mean.onnx`, `crop_index.faiss` (2,144 vectors), `train_labels.npy`, `classes.json`, `model_meta.json`.

---

## 2. Download & Stage Versioned Assets

From Google Drive (`MyDrive/KissanSevaAI_Phase1/versions/<VERSION_TAG>/model_assets/`), download all artifacts into a separate versioned directory:

```bash
mkdir -p ml-service/model_assets_versions/v2_full_dinov2_vits14
```

Expected files in `ml-service/model_assets_versions/v2_full_dinov2_vits14/`:
- `dinov2_vits14_cls_mean.onnx`
- `crop_index.faiss` (normalized `IndexFlatIP`, full training set only)
- `train_labels.npy`
- `classes.json` (must match the 67-class order 1:1)
- `train_image_mapping.csv` (source path, class ID, SHA256, dHash provenance)
- `model_meta.json`
- `SHA256_MANIFEST.json`

---

## 3. Integrity & Parity Verification (Before Activation)

Run checksum and schema verification against the staged directory before routing live traffic:

```bash
python3 - <<'PY'
import json, hashlib
from pathlib import Path
import faiss, numpy as np

v_dir = Path("ml-service/model_assets_versions/v2_full_dinov2_vits14")
prod_classes = json.loads(Path("ml-service/model_assets/classes.json").read_text())
new_classes = json.loads((v_dir / "classes.json").read_text())
assert prod_classes == new_classes, "Class ordering mismatch against production classes.json!"

manifest = json.loads((v_dir / "SHA256_MANIFEST.json").read_text())
for fname, info in manifest.items():
    digest = hashlib.sha256((v_dir / fname).read_bytes()).hexdigest()
    assert digest == info["sha256"], f"Checksum mismatch on {fname}"

labels = np.load(v_dir / "train_labels.npy")
idx = faiss.read_index(str(v_dir / "crop_index.faiss"))
assert idx.ntotal == len(labels) and idx.ntotal > 2144
assert idx.metric_type == faiss.METRIC_INNER_PRODUCT
assert abs(float(np.linalg.norm(idx.reconstruct(0))) - 1.0) < 1e-4
print(f"Verified staged index: {idx.ntotal} vectors, {len(new_classes)} classes, L2-normalized IndexFlatIP.")
PY
```

Also verify zero train/val/test leakage from `splits.csv`:
- Confirm `len(set(splits[splits.split == 'train'].sha256) & set(splits[splits.split != 'train'].sha256)) == 0`.
- Confirm `len(labels) == len(splits[splits.split == 'train'])`.

## 4. Non-Destructive Staged Activation via `CROP_MODEL_DIR`

`ml-service/app.py` honors the environment variable `CROP_MODEL_DIR`. Activate the staged version without touching `ml-service/model_assets/`:

```bash
export CROP_MODEL_DIR="/Users/manthangarg/Desktop/kissansevaai-main/ml-service/model_assets_versions/v2_full_dinov2_vits14"
cd ml-service && venv/bin/python3 app.py
```

Verify `/health` reports the new `reference_images` count and `model` metadata:
```bash
curl -s http://127.0.0.1:8000/health | python3 -m json.tool
```

Run pytest against the staged directory:
```bash
CROP_MODEL_DIR="$(pwd)/ml-service/model_assets_versions/v2_full_dinov2_vits14" ml-service/venv/bin/python3 -m pytest ml-service/tests/ -v
```
*(Note: update expected `reference_images` assertion if testing `v2` directly, or run validation smoke tests via `TestClient`.)*

---

## 5. Instant Rollback Procedure

If memory usage, latency, or held-out validation metrics regress, roll back immediately with zero file restoration:

```bash
unset CROP_MODEL_DIR
# or explicitly:
export CROP_MODEL_DIR="/Users/manthangarg/Desktop/kissansevaai-main/ml-service/model_assets"
```

Restart `ml-service/app.py`. The original 2,144-vector baseline remains untouched in `ml-service/model_assets/`.
